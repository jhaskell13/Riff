# Riff audit — November 2026

Scope: the whole app after Phase 3. Laravel idiom, security, concurrency,
performance, and comment hygiene. Everything marked ✅ was fixed in this
pass; everything under "Recommended" is deliberate work that was *not* done,
with the reason.

Baseline at the end: **657 tests passing**, pint clean, PHPStan level 6
clean, `composer audit` and `npm audit` clean.

---

## Fixed

### 1. A race on likes could 500 a user ✅

`ReactionController::like()` ran `exists()` and then `attach()`. Two taps
that race both pass the check; the second hits the pivot's unique index and
throws. The transaction around it did not help — it is a read-then-write,
not a conflict the transaction serialises.

Replaced with a single `insertOrIgnore`, whose affected-row count decides
whether the counter moves. Atomic on all three drivers. `unlike()` already
used `detach()`'s return value, which is safe; its transaction was redundant
and went.

Regression test: `WallTest::a_duplicate_like_is_absorbed_rather_than_erroring`.

### 2. Two digest runs could both email the same person ✅

`DigestSender::sendTo()` read `digest_sent_at`, decided, sent, then wrote.
Two overlapping runs — a scheduler that fires twice, or someone running
`riff:send-digests` by hand while cron is going — both read the old value and
both sent.

Now the slot is **claimed with a conditional `UPDATE`** carrying the same
predicate as the selection query; only the run whose update matched a row
sends. The "never send an empty digest" rule is preserved by building the
digest first and claiming only if it has content.

Regression test: `WeeklyDigestTest::two_overlapping_runs_do_not_both_send`.

### 3. The artist page asked the same authorization question eight times ✅

A member viewing their own artist page ran the membership `EXISTS` **8×** and
the follow `EXISTS` 2×, because `canManage`, `canBlock`, `canPostAsArtist`,
`wallBans` and the three gate calls inside `WallViewer` each re-derive it.

The three facts are now computed once in the controller and reused. 37 → 33
queries. `ArtistPolicy::postAsArtist`, `::update` and `::moderateWall` are
all literally "is this user a member", so reusing one boolean for the
*render* is sound; **every write path still goes through `$this->authorize()`**,
which remains the authority.

An earlier attempt cached the relations on the `User` model
(`loadMissing`) and was **backed out**: three tests failed because
`actingAs()` reuses one `User` instance across requests, so the cache went
stale. That is the same footgun that got a `User`-level memo rejected during
Phase 3, and it was right to reject it twice.

### 4. Strict models in development ✅

`Model::preventSilentlyDiscardingAttributes()` is now on outside production.
A field passed to `create()`/`fill()` that is not fillable used to vanish
silently — that is exactly how a test fixture set `lineup_entries.status`,
had it ignored, and quietly asserted the opposite of what it claimed.

The other two halves of `shouldBeStrict()` are **not** on, measured rather
than assumed:

| guard | failures if enabled |
|---|---|
| `preventSilentlyDiscardingAttributes` | 0 — adopted |
| `preventAccessingMissingAttributes` | 18 |
| `preventLazyLoading` | many |

Both are worth adopting; neither is a one-line change. See Recommended.

### 5. No security headers ✅

Laravel sets none. Added `App\Http\Middleware\SecurityHeaders`:
`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`,
`Permissions-Policy`. Each one is justified by something Riff actually does
— uploaded images on a media disk, URLs that name a real venue, a map that
asks for location explicitly rather than silently.

Deliberately **no CSP**: Riff embeds third-party players, loads map tiles
from a provider, and serves a Vite bundle. A wrong CSP breaks the map
silently. That is a task, not an audit line.

### 6. Comment bloat ✅

Phase 3 files ran 25–72% comment lines. The worst (`Commentable.php` at 72%)
had three paragraphs of prose above a six-method interface.

Trimmed across the DTOs, enums, services and the models I touched — most
files are now 18–27%. The rule applied: **keep a comment that records a trap
or a decision** (the `posts.comments` shadow, the SQLite float-vs-expression
binding, why a memo was rejected); **cut anything that restates the code**.
No comment that explains *why* was removed.

### 7. Minor idiom ✅

`Post::query()->whereRaw('1 = 0')->get()` as a way to spell "empty
collection" → `new Collection`.

## Checked and clean

- **Authorization.** Every state-changing route either calls
  `$this->authorize()`, delegates to a method that does, or is scoped to
  `$request->user()`'s own rows. Audited by walking `route:list` and
  matching each action against its controller body. The apparent gaps
  (`ShowRsvpController@destroy`, `ArtistBlockController@destroy`) only ever
  touch the caller's own pivot rows — no IDOR.
- **SQL injection.** All `whereRaw`/`orderByRaw`/`selectRaw` use literal SQL
  with `?` placeholders; the only interpolated fragments are class constants
  and internally-built distance expressions. No user input reaches SQL text.
- **Mass assignment.** Every model uses `$fillable`, never `$guarded = []`.
  The sensitive columns (`is_moderator`, `clicks`, `slug`, `image_path`,
  `lineup_entries.status`, `host_artist_id`, `cancelled_at`) are excluded and
  covered by `MassAssignmentTest`.
- **Unique constraints** exist on every pivot that matters, so the remaining
  check-then-write paths degrade to a failed insert rather than bad data.
- **`env()` outside config:** none. (It returns null once config is cached.)
- **Debug leftovers:** no `dd`, `dump`, `var_dump`, `ray` or `console.log`.
- **Dependencies:** `composer audit` and `npm audit` both clean.
- **Email safety:** every seeded account is on an RFC-reserved `example.*`
  domain, enforced by `PilotDatasetTest` against both the dataset file and
  the seeded database. A demo digest cannot reach a real inbox.
- **Query growth.** The costs that matter are bounded, not linear: `WallTest`,
  `WallModerationTest`, `ShowThreadTest` and `YourSceneTest` each assert that
  query count **does not grow** with wall contents, moderation history,
  thread length or follow-list size.

## Recommended, not done

1. **Adopt `preventAccessingMissingAttributes`** (18 failures). Most come
   from serialising a model after a narrowed `select` — Inertia does this
   with the auth user. Fixing it means being explicit about what each page
   serialises, which is good hygiene and a day's work.
2. **Adopt `preventLazyLoading`.** The highest-value guard and the most
   invasive: it turns every unplanned lazy load into an exception. Worth
   doing before real traffic, behind its own branch.
3. **A Content-Security-Policy**, designed around the embed providers and
   tile host rather than bolted on.
4. **Watch `failed_jobs`.** Notifications, geocoding and digests are all
   queued; nothing currently alerts when they fail. The ROADMAP already
   flags this as pre-launch work and it is the single biggest operational
   gap.
5. **Remaining check-then-write races** — `ListingReplyController`
   (one reply per person) and `WallModeration::ban()`. Both are protected by
   unique indexes, so the failure mode is a 500 rather than bad data, and
   both are low-frequency. Fix with `insertOrIgnore` when convenient.
6. **`artist page (guest)` is 22 queries.** Not an N+1 — it is the page's
   sections (wall, comments, replies, shows, listings, support links, scene
   links, fan counts). Worth revisiting only if the artist page gets slow
   with real data.
